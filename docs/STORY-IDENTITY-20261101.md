# 故事配置、用户身份与剧情选项（2026-11-01）

> 后续协议与逐轮选项修正见 [UI-STORY-UNIFICATION-20261101.md](UI-STORY-UNIFICATION-20261101.md)。现已用 label/reply 对象分离展示与实际发言，旧字符串选项会重新生成；开场与漏返选项可按当前回合补齐，增加取消、过期回合和保存失败保护。下文为前一阶段的实现与验证记录。

## 接续来源

读取本机 Codex 会话 `01a190ab-8d35-7161-b081-7c20eb6dd767` 的最新用户需求及中断记录。用户已确认“完全自主”指自由输入推进故事，不是让模型自动连续发言；另一模式在每轮回复后提供可点击选项，同时保留自行输入。原会话停在 Rust 故事存储的完整性标识问题，ArkTS 尚未接入。

## 实现

- 新增 `StoryPage.ets`：从聊天首页加号、角色开始聊天及聊天内角色创建入口选择角色后，进入独立二级页面。配置故事名称、背景、叙事风格、补充规则、开场白、聊天模式及 2–6 个选项。保存成功后进入新对话，失败保留表单；读取失败可重试，保存期间阻止系统返回及重复提交。
- 聊天菜单新增“故事与聊天模式”，可对当前单人对话修改配置。开场白仅在创建时填写，不覆盖已有消息；保存通过 `storyRevision` 通知聊天页重新读取。故事配置独立于角色卡。
- `NativePreferencesPanel.ets` 支持系统相册选择头像、恢复默认、修改名字和描述。头像通过原有沙箱导入链路上传，上传前检查 20 MB 上限，上传后清理临时文件；点击保存才更新生效身份。聊天气泡使用当前昵称和头像。
- 人设描述可插入角色描述之前/之后、聊天记录之前/之后、聊天记录指定深度。记录插入支持系统/用户/助手角色及 0–100 深度，由 Rust 真实参与提示词装配，不改写历史消息。
- `NativeStory.ets` 封装既有 Rust 故事命令；普通聊天生成传递 `fileName`，按当前对话配置提示词。回复交由 Rust 清理并校验剧情选项，正文与选项一起持久化；重开会话可恢复选项。
- 只展示最后一条助手消息的有效选项；点选作为用户消息发送。正在生成、准备请求或保存回复时阻止重复操作；已有草稿或附件时不覆盖草稿。流式显示隐藏选项协议块及其不完整起始标记。
- 新会话生成 UUID 完整性标识及唯一文件名，修复原扩展存储缺失标识和同秒连续创建冲突。旧会话无故事配置时默认自由模式；首次保存故事配置补齐标识，保留已有消息和完整性校验。
- 保留现有主题、握姿加号、普通模糊面板及导航/按钮材质；新页面复用 PageSurface、PageHeader、共享控件和减少动态效果设置。

本轮故事配置与剧情模式针对单人对话，未扩展群聊的剧情模式。

- `story-group-validation.log`：已有群聊存储测试单独运行通过。

## 首次会话引导后续修正

按用户追加要求，首页“故事，从一句话开始”只在从未成功创建会话时展示。使用 `PersonalizationStore` 的 `storyWelcomeDismissed` 持久化标记，创建故事成功立即设置；已有单人会话或有聊天记录的群聊自动迁移为已完成首次创建。后续删除全部会话不会清除标记，读取会话列表未成功前不展示引导，避免把加载中当作首次使用。API 26 构建通过，模拟器保留原有会话时确认卡片隐藏，强制停止并冷启动后仍隐藏。没有为测试删除用户原有对话。
