# HarmonyTavern 界面改造记录

## 范围

本次只调整 ArkUI 页面、组件、主题资源和 UI 窗口行为。保留后端、原生库、聊天生成与取消、数据存储、导入、模型连接及其他业务方法。原始源码备份位于 `ui-backup-20261030/ets`。

## 最新调整：共用玻璃底栏

- 手机导航与聊天输入使用 Navigation 外部的同一个常驻玻璃底座。进入聊天时底座从导航宽度过渡到输入宽度，输入控件淡入；返回时反向恢复。玻璃镜片不参与透明度转场。
- 聊天入口使用 `customNavContentTransition` 与 `UIContext.animateTo`，动画完成后调用 `finishTransition`，提供超时及路由状态收尾。其他页面使用系统 `SLIDE_RIGHT` 平移转场。减少动态效果时关闭位移与过渡时长。
- 导航从 68vp 缩至 56vp。输入栏默认 56vp，长文本增长至四行后可内部滚动，保留 44vp 按钮触摸区域。
- 删除 Tabs 底部固定留白，将末尾避让放进 List 内容偏移、Grid 尾项或 Scroll 内部。导航下面不再铺整块遮罩，内容可滚入玻璃背后。系统手势区仅用于定位浮栏，不再缩短首页内容。
- 底栏使用 API 22 的 `backgroundEffect`，半透明色、饱和度、亮边和微弱反光渐变；浅色与深色分别取色。模糊关闭或窗口失活时使用实色回退。
- 聊天页只常驻紧凑标题、消息和输入栏；切换会话、模型、摘要、搜索、重试收进右上角菜单。编辑、删除、图片、停止生成入口保留，错误仍显示。键盘采用 RESIZE 避让。
- `ChatDockState` 仅在页面与浮栏之间同步输入、生成状态及事件回调，发送、停止、附件上传仍使用原页面处理逻辑。

主页、资料库和详情页的主滚动区域统一由该容器管理，让内容可以经过页头后方；保留有明确高度的内部编辑/列表区域。聊天页保留原消息 Scroller 与滚到底部逻辑，接入同一个渐变容器。共用 `PageHeader` 采用 72vp 高度、圆形玻璃返回按钮与一致的双行标题。

### 服务商目录、协议与动态模型

共 34 个服务入口，分为“官方直连”和“第三方与云平台”。目录覆盖后端现有 20 种来源，并为通义千问、火山方舟、百度千帆、腾讯混元、智谱中国站、阶跃星辰、Mistral、零一万物、百川、Perplexity、Together、Fireworks、Ollama 和 LM Studio 提供兼容入口。目录不是对市场全部服务商的穷尽声明；未列出的兼容服务可使用自定义入口。

自定义入口可选择 OpenAI Chat Completions、OpenAI Responses、Anthropic Messages、Gemini GenerateContent、Gemini Interactions 五种后端已支持的协议。OpenCode 按其支持范围选择协议，Cohere、Workers AI、Bedrock 与 Vertex AI 继续使用现有专用适配。Workers AI 提供账号字段，区域型服务提供区域字段；Vertex AI 当前展示 Express API Key 模式。

“保存并获取模型”直接调用现有 `get_chat_completions_status` 命令，填写地址与密钥后无需先填写模型。获取结果可搜索、分批展开并选为默认模型；手动填写入口始终保留。修改模型无需重复输入已保存密钥。聊天来源、模型下拉、测试请求与生成请求共用服务配置。MiniMax、Vertex AI 的后端模型状态接口返回 bypass 时，明确提示手动填写；错误和空列表不显示为连接成功。实际可用模型以服务商返回结果、账号权限与选定区域为准。

配置与模型列表在 ArkUI 本地偏好中保存；密钥仍由现有原生密钥接口保存。每个兼容服务记录独立 `secret_id`，包括无密钥的本地服务，防止共享 custom 适配器误用另一服务的密钥；原生服务继续遵循其激活密钥。旧 custom 配置只迁移明确的原配置引用，掩码不会作为 URL 或模型；若旧存储不允许返回明文地址，需要重新填写地址与模型，密钥引用仍保留。自定义端点继续遵循原有授权流程，取消授权不会被报告为测试成功。此次未修改 Rust 后端、聊天存储或流式生成流程。

- 根容器、首页和全部 28 个 NavDestination（主导航 27 个、服务商内部详情 1 个）具有主题背景。页面切换期间 Navigation 尺寸固定，底部安全区避让由滚动内容承担。

### 水滴连接与圆球挤出

本节替代前文的原生菜单缩放方案。加号、聊天顶部更多、左右消息操作和角色菜单统一使用 `OriginPanel`，以点击当时测得的屏幕坐标为来源，在弹层宿主内换算坐标。收回时重新测量同一个来源控件，来源消失则保留捕获位置。菜单宽度最多 224vp，内容可滚动；完整子面板保留原有可见范围、键盘和安全区适配。

轮廓先从来源球体拉出一个纵向水滴，再以弹簧展开为面板；上下方向由入口在屏幕的位置决定。`LiquidContour` 使用三次贝塞尔曲线连接球体与面板，接触点跟随面板圆角，腰部逐渐收细后断开。关闭时重新形成连接，面板收成水滴并回到原球体。面板内容保持正常排版尺寸，随轮廓展开淡入；玻璃采样层不做整体透明度动画。顶部模型标题保留独立的底部弹起与向下退出。
