# HarmonyTavern

**让故事自由生长，把熟悉的酒馆体验带到原生鸿蒙。**

HarmonyTavern 是一款使用 **ArkTS / ArkUI + Rust** 构建的 HarmonyOS 原生 AI 角色扮演与故事创作应用。围绕 SillyTavern 生态中的角色卡、世界书、聊天记录和扩展数据，项目提供原生界面与持续适配，并加入创造模式、辅助模型、上下文精简和使用统计等功能。

从导入喜欢的角色，到构建世界、接入模型，再到展开一段长期故事，HarmonyTavern 希望让这些操作在手机上自然、顺手，也让长时间阅读与流式对话更加轻快。

> 当前版本仍在持续开发。SillyTavern 生态兼容分为数据兼容、扩展管理和插件运行三个层面；目前已具备前两者的部分能力，尚未提供完整的 SillyTavern 浏览器插件运行环境。下文列出具体范围。

## SillyTavern 生态兼容

### 带着角色与故事继续创作

项目以 TauriTavern 的 Rust 核心为移植基础，在鸿蒙端重建角色、资料库、聊天和设置界面，让已有创作资料可以在原生交互中继续使用。

| 内容 | 当前能力 | 兼容说明 |
| --- | --- | --- |
| 角色卡 | 导入、创建、编辑与角色管理 | 可继续使用已有角色资料；复杂扩展字段的显示与执行效果需分别确认 |
| 世界书 | 导入、条目编辑、启用与禁用、绑定故事 | 当前将所选书的启用条目作为背景；尚未等价实现 ST 的关键词、递归激活及完整位置与预算规则 |
| 聊天记录 | 导入 SillyTavern JSONL / JSON，打开历史会话继续聊天 | 特殊插件附加数据的实际作用取决于对应功能是否已适配 |
| 预设与提示词 | 预设管理、角色与用户人设装配、基础宏替换 | 已支持 `{{char}}`、`{{user}}` 等基础替换；完整 ST 提示词引擎与复杂宏仍在完善 |
| 群聊 | 群组管理、成员静音、按顺序或手动指定成员回复 | 尚未完整复现 ST 的自然激活概率及全部群聊生成策略 |
| 扩展数据 | 会话级命名空间与键值数据管理 | 可用于保存和管理扩展状态；数据可读写不代表对应插件已能执行 |

### 扩展管理与插件适配

应用已提供扩展仓库安装、列表查看、版本查询、更新和删除入口。安装与更新需要网络可达，也受仓库访问权限影响。

不同插件对 SillyTavern 的依赖不同，因此兼容情况需要逐项判断：

| 插件或扩展类型 | 当前情况 |
| --- | --- |
| 以角色卡、世界书、聊天文件承载内容的扩展 | 可利用已有数据入口；附带脚本与特殊字段需单独适配 |
| 依赖扩展存储的工具 | 已有存储和管理接口；仍需对接工具自身的执行逻辑 |
| 依赖浏览器 DOM、jQuery、ST 前端事件或模块的插件 | 当前原生界面未提供完整运行环境，不能直接保证可用 |
| 酒馆助手、MVU 等脚本体系 | 暂未完成专项兼容验收，不列为已支持插件 |
| 自定义 HTML / JavaScript 状态栏、CSS 主题 | 不直接执行或套用；应用提供原生创造模式状态栏与主题系统 |
| 依赖 Node.js 或桌面宿主的服务端插件 | 需另行部署或设计鸿蒙适配，不能直接作为原生扩展运行 |

**扩展安装成功不等于插件运行成功。** 当前重点是延续创作数据与常用工作流，同时将适合手机的能力做成原生功能；完整第三方插件兼容仍是后续适配方向。

如果反馈某个插件的兼容问题，请附上插件仓库、版本、复现步骤、预期行为和实际结果。分享日志前请移除 API Key 与私人聊天内容。

## 为故事创作加入的新功能

### 创造模式：让世界状态看得见

在普通对话和剧情选项之外，创造模式可以根据世界书、人物资料、已发生的剧情和你的展示需求，生成原生状态界面。

- **人物指标**：按世界设定显示生命、体力、灵力或其他指标，不强制所有故事使用同一套属性。
- **状态效果**：展示受伤、中毒、增益等状态及其说明。
- **独立背包**：查看物品、数量与用途。
- **当前位置**：按区域、场所与具体位置组织信息。
- **持续保存**：状态随有效回复或手动生成结果保存，重新进入会话后可恢复。

你可以直接描述：“显示主角的生命与灵力、负面状态、丹药数量和当前房间。”应用会把模型返回的结构化数据映射到原生组件。

未确认的数值和物品数量会标为未知。创造模式展示模型整理的剧情状态，不是确定性的战斗或库存计算引擎；它也不要求执行模型生成的网页脚本。

### 辅助模型：为创作准备分配独立帮手

辅助模型可从服务商管理中已配置的模型里选择，与主聊天模型分别使用，承担：

- 整理连接配置，辅助填写服务商信息。
- 根据需求生成故事草稿，预览后由用户填入和修改。
- 为创造模式手动生成状态栏数据。

切换辅助模型不会改变主聊天模型。辅助任务会产生对应服务的用量；正常回复及随回复产生的状态更新仍使用既有主模型流程。

### 长期对话与上下文精简

故事越来越长时，可以按需调用当前模型，将较早历史整理为摘要，同时保留近期原文、角色设定和故事背景。聊天原文保留，可恢复完整上下文。

应用提供独立的输入上下文预算与输出长度设置，超出预算时明确提示。精简需要额外模型调用，实际 Token 消耗取决于模型、背景资料和摘要长度。

### 模型连接与使用统计

- **统一服务商管理**：区分官方直连与第三方、云平台入口，支持兼容服务和自定义端点。
- **模型选择**：获取、搜索或手动填写模型，配置连接并测试。
- **生成控制**：调整温度、Top-P、回复长度、上下文预算及受支持模型的推理强度。
- **思考内容展示**：可折叠查看接口实际返回的思考内容或摘要，是否可用取决于模型与协议。
- **本地使用统计**：查看活动热力图、模型排行、请求来源及 Token 用量，支持不同时间范围。

统计优先使用接口实际返回的数据；未提供的用量显示为未知，本地上下文估算不作为服务商账单。

## 原生鸿蒙，围绕流畅交互设计

HarmonyTavern 的主要页面使用 **ArkUI 原生组件**构建，Rust 核心通过 Node-API 提供数据与模型能力。聊天、角色、资料库和设置均采用原生页面。

流畅度优化落在具体使用路径上：

| 使用场景 | 已有优化 |
| --- | --- |
| 阅读长聊天 | 使用 `List + LazyForEach` 惰性构建消息，减少一次性创建大量界面的开销 |
| 接收流式回复 | 批量合并流事件后更新正文与思考内容，减少重复渲染 |
| 浏览会话列表 | 读取会话摘要，避免为列表预览加载全部聊天正文 |
| 发送长历史 | 后端读取已持久化历史，减少完整历史在 ArkTS 与 Rust 之间重复序列化 |
| 边生成边阅读 | 向上翻阅时保持阅读位置，可手动回到最新回复 |
| 页面与菜单切换 | 统一弹簧过渡、按压反馈、来源展开动画及减少动态效果设置 |

界面支持深浅色模式、玻璃材质和可调外观，在设备能力不足或关闭模糊时使用兼容显示。交互设计兼顾长时间阅读，减少装饰对正文的干扰。

目前已有编译、客户端回归和模拟器检查；真机帧率、极长会话内存与不同设备表现仍需持续验证，暂无统一性能基准或固定帧率承诺。

## 四种 RPG 主题，四种故事氛围

| 主题 | 视觉风格 |
| --- | --- |
| 冒险者手札 | 羊皮纸、古铜饰边与森林墨绿，像随身携带的冒险日志 |
| 绯樱物语 | 和纸纹理、朱印与樱色，适合细腻安静的日式故事 |
| 像素旅人 | 像素城镇、方形面板与掌机配色，带来复古 RPG 氛围 |

每套主题均提供浅色和深色版本，并适配页面、图标呈现、边框与装饰。素材随应用打包，运行时无需联网加载主题图片。

设计预览位于 `opendesign/mockups/rpg-themes/index.html`；素材来源与许可说明见 `entry/src/main/resources/rawfile/rpg-theme-assets.txt`。

## 开始使用

1. 安装适配设备的 HAP；本地调试签名包需要按开发设备的签名与授权要求安装。
2. 在「设置 → 服务商管理」填写连接信息、保存凭据并选择模型。
3. 在资料库导入或创建角色卡，按需准备世界书。
4. 在聊天首页创建对话，选择角色、世界书与聊天模式。
5. 如使用创造模式，填写状态栏需求，再手动生成或随对话更新状态。
6. 在外观设置中选择主题，并定期备份重要故事。

AI 生成通常需要可用网络及模型服务。连接 Ollama、LM Studio 等本地服务时，需要设备能访问相应服务地址；这不代表模型直接在鸿蒙设备内运行。

## 开发与构建

- **界面**：ArkTS / ArkUI。
- **核心**：Rust，通过 Node-API 与鸿蒙交互。
- **设备**：工程声明支持手机和平板。
- **SDK**：当前工程配置最低兼容 API 22，目标 API 26；部分材质按系统能力适配。

使用 DevEco Studio 打开工程，配置对应 HarmonyOS SDK、NDK 与 Rust 工具链，并使用自己的签名配置。当前构建脚本包含本机 SDK 路径，首次构建需按环境调整。

在项目根目录构建手机原生库：

```powershell
powershell -File native/scripts/build.ps1 -Arch arm64-v8a
```

构建 x86_64 模拟器调试库：

```powershell
powershell -File native/scripts/build.ps1 -Arch x86_64 -Debug
```

脚本将原生库复制到对应的 `entry/libs/` 架构目录，之后在 DevEco Studio 构建、签名并运行应用。构建和打包不会替代真机或真实模型服务的端到端验证。

## 从源码构建

以下文件包含私有信息，不在仓库中，克隆后需要自行准备：

- **签名配置**：复制 `build-profile.json5.example` 为 `build-profile.json5`，在 DevEco Studio 中生成你自己的调试签名并填入 `signingConfigs`。
- **内置辅助模型密钥（可选）**：复制 `entry/src/main/resources/rawfile/builtin/siliconflow.key.example` 为同目录下的 `siliconflow.key`，写入你自己的硅基流动 API Key。该文件随安装包分发，任何拿到安装包的人都能提取，请只使用有用量上限的专用密钥。不提供时，内置助手显示为不可用，其他功能不受影响。
- **原生库**：`entry/libs/` 下的 `.so` 由脚本生成，先运行 `native/scripts/build.ps1 -Arch x86_64`（模拟器）和 `native/scripts/build.ps1 -Arch arm64-v8a`（真机），再用 `scripts/build-hap.ps1` 构建 HAP。
