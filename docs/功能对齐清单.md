### 10.5 重要架构发现（影响"世界书/群聊"这类功能）

### 10.9 第四批（同日 13:00–13:20）：用户 + 备份中心

#### 用户 → `pages/UserPage.ets`（新增包装 `get_user` / `update_user`）

能力：用户列表、新建/删除、用户名与头像路径、主题、界面设置（avatar_style / chat_display / font_size / blur_strength / show_timestamps）、生成参数（max_context_length / response_length / temperature / top_p / top_k / repetition_penalty），整体保存（`UpdateUserDto.settings` 是整体替换，页面把三块都带上）。

实测：页面正常打开；`get_all_users` 返回空 → 显示空态。

### 10.14 消息编辑/删除：查证结论（重要）

把 263 条命令里所有 `update_* / set_* / delete_* / write_*` 全过了一遍，**没有一条能改/删单条聊天消息**：

风险：绕过后端写文件，必须成对做"写文件 + 清缓存"，否则读到旧内容。

#### (2) 真 bug 一：ErrorBanner 永远不刷新（全工程 23 处）

**症状**：后端明明报错，hilog 有 command xxx failed，界面上什么都没有。

**根因**：ErrorBanner 是 @Builder 函数，参数**按值传递**。ArkUI 的规定是

所以它一直渲染的是**首帧的空字符串**。

**修法**：改成 @Component ErrorBannerView { @Prop text: string }（@Prop 会跟随父状态），

**影响**：这个 bug 之前把「后端报错」伪装成「按钮点了没反应」，
我前面几次误判（例如世界书开关、群聊、搜索按钮"没生效"）有一半是它造成的。

#### (3) 真 bug 二：鸿蒙建的会话没有 chat_metadata.integrity

create_chat 命令只吃 {character_name, user_name, first_message}，**没地方传 metadata**；

### 10.36 按官方 ArkUI 文档校准动效 + 界面收尾（P9-5）

**文档读取情况（避免"假装读过"）**

  精读 rkts-spring-curve.md、rkts-enter-exit-transition.md、rkts-animation-smoothing.md。

**文档直接改掉的三处做法**

| 依据 | 结论 | 落地 |
| --- | --- | --- |
| 弹簧曲线：springMotion(response, dampingFraction, overlapDuration)，时长由曲线自动算，**会停止同属性正在跑的动画并继承其速度** | 弹簧适合"跟手→离手"和可打断状态，不适合一次性入场（会弹） | 入场改 Curve.Friction + duration，弹簧只留按压/选中 |
| 出现/消失转场：官方错峰示例用 Curve.Friction + nimation({delay: INTERVAL*index}) | 错峰用延迟而不是弹簧 | staggeredEntrance() 改为 duration+delay |
| 转场："消失时如果不给所有父控件加转场，子项消失转场不生效" | 父级要挂 TransitionEffect.opacity(0.999) | 新增 parentTransitionGuard() 挂到网格容器 |
